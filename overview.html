1. What this is

The 864zeros-publish repository is the central content and data store for the 864zeros ecosystem. Its job is to author, structure, and publish clean, validated JSON assets — organized into namespaces (shared/ for ecosystem-generic content and apps/<name>/ for app-specific suites) — that can be consumed by any property across the 864zeros umbrella. Every record pairs a public-domain source with original 864zeros writing, which is precisely what makes the output legally clean, defensible, and a genuine 864zeros intellectual asset rather than a re-shipped commodity.

The guiding rule throughout: the paraphrase is the product. The scripture text is the citable anchor; the original plain-English rendering is the value 864zeros owns and can deploy anywhere.

Coverage

  • New Testament: 100% of chapters represented (epistle books cover every chapter; Gospels one verse per chapter).
  • Old Testament: devotional high points of every book — pure-genealogy and graphic-only narrative chapters are intentionally omitted (documented per file), so coverage is "most substantive chapters," not "every chapter."

Translation policy

KJV King James Version anchors the New Testament and most of the Old Testament — it matches the app's existing daily-verse content and is cross-checkable against the local KJV source. WEB World English Bible anchors Psalms & Proverbs only (chosen before KJV became the standard), with the divine name rendered "the Lord."

Known, deliberate inconsistency: Psalms & Proverbs use the WEB anchor; everything else uses KJV. This was a conscious call (documented), and is trivially fixable if one uniform translation is ever wanted.

4. The 864zeros Media-DAGR Publishing Engine

Every asset in the 864zeros publishing ecosystem is authored and processed through the DAGR Pipeline (Distillation → Augment → Generation → Review/Refine) — adapted from the AETHER/AEC flagship architecture (S06_DAGR_METHOD.md).

DAGR Core Architecture

1. Distill (Deterministic · <0.1ms): Extracts core structure from source scripture, recovery passages, or study lessons (intent, concrete physical metaphors, entities, constraints) using standard library regex and JSON parsers — zero LLM cost, zero hallucinations.

2. Augment (Knowledge & Style Grounding): Injects domain grounding rules: the Dual-Rendering Translation Trinity (KJV + WEB + 2026 Plain Language), authentic pen & ink mark-making grammar (fountain pen strokes, zero shading, 40% asymmetric line weight), negative suppression tokens, and multi-tiered spatial staging.

3. Generate (The Non-Deterministic Call): Executes the single generative call to create the base asset: visual structural line draft, spoken meditation audio synthesis, or reflection journal prompts.

4. Review / Refine (Accountability & Distillation Loops): Closes the loop through deterministic verification passes:
• Visual Loop A (Clutter Stripping): Removes interior scratches and micro-hatching down to pure perimeter contour lines.
• Visual Loop B (Line-Weight Calibration): Selectively thins 40% of secondary lines by 50% for dynamic calligraphic stroke variation.
• Card Superimposition: Assembles 1200×900 high-resolution typographic cards with zero third-party runtime dependencies.
• Legal & Clinical QA: Enforces 100% public-domain provenance and clean commercial licensing.

5. Methodology & conventions

  • Dual rendering. text = verbatim public-domain scripture (the citable anchor). plain = original 864zeros writing in warm, plain 2026 English (~grade 6–8). Both preserved; the scripture is never replaced by the paraphrase, so citations never misrepresent.
  • Provenance. Scripture text was pulled as whole-book clean JSON, then verses selected and validated locally, and cross-checked against a local KJV copy. Nothing was quoted from memory into a shipped record.
  • Divine name. KJV renders "the Lord" as-is. WEB's "Yahweh/Yah" was adapted to "the Lord" (subject/possessive) and "Lord" (direct address) for familiar, cross-app reading.
  • Normalization. Straight ASCII quotes/apostrophes; proper-name en-dashes → hyphens; wrapping parentheses, editorial colophons, and "Selah" markers dropped for clean standalone display; UTF-8 with no byte-order mark.
  • No review gates. This content is original, 864zeros-authored; the author is the reviewer. No clinical or theological sign-off flags are attached.
  • Validated. Every file parses; _meta.count matches actual records; no empty text/plain; no stray curly characters; the manifest total reconciles to 834.

5. Key decisions on the record

The paraphrase is original 864zeros content — not a published simple translation.
Alternative rejected: use a public-domain simple-English Bible (e.g. Basic English) as the "plain" layer. Reason: that would be a third party's dated text, non-differentiated and non-owned. Writing our own in a fresh 2026 voice is the entire point.
Keep the exact scripture beside the paraphrase (dual rendering), never replace it.
Alternative rejected: ship only the modern rewrite under the citation. Reason: a citation is a truth claim — the actual verse must sit next to our authored line.
"Several key verses per chapter" for the epistles and OT (not one-per-chapter, not every verse).
Alternatives rejected: a single flagship verse per chapter (too sparse for study use) or every verse (~all ~31,000 — a commodity re-ship, not curation).
Bulk whole-book sourcing over per-verse API calls.
Alternative rejected: fetch each verse individually (hit rate limits) or scrape local PDFs (error-prone verse boundaries). Whole-book JSON is exact and fast.

7. Provenance & licensing posture

  • Scripture text: King James Version and World English Bible — both public domain.
  • Big Book passages: derived from the 1939 first edition of Alcoholics Anonymous (public domain), re-authored into original content.
  • All plain renderings, affirmations, and modernized passages: original 864zeros writing — 864zeros intellectual property.
  • Net: zero third-party license obligations. Nothing here depends on a copyrighted translation or a paid source.

8. Runtime note — content filtering

Because this content ships as static JSON assets, no live AI/API call is needed at runtime. This matters: Anthropic's API output filter can flag graphic scriptural imagery (e.g. Revelation) if raw verses are re-sent through a live model call. Loading the JSON directly avoids that entirely — do not round-trip the raw text through an API in production.
